# Службы и автозапуск

В MyOS есть небольшой менеджер служб и команда `/bin/systemctl` с интерфейсом,
похожим на systemctl. Это собственная реализация, а не порт systemd.
Менеджер стартует после подключения диска, перед оболочкой входа.

## Готовые службы

Команды изменения состояния выполняются после входа под root:

```sh
systemctl                         # список служб, PID, состояние и код выхода
systemctl enable desktop          # рабочий стол при следующей загрузке
systemctl start desktop           # запустить сейчас
systemctl enable --now httpd      # включить автозапуск и запустить HTTP-сервер
systemctl status httpd
systemctl restart httpd
systemctl stop httpd              # остановить; автозапуск сохраняется
systemctl disable --now httpd     # остановить и выключить автозапуск
systemctl disable desktop         # при следующей загрузке останется консоль
```

При установке примеры `desktop.service` и `httpd.service` отключены. `make install`
не перезаписывает существующие определения служб и настройки автозапуска.
Суффикс `.service` в командах можно опускать. `enable` и `disable` без `--now`
изменяют только следующую загрузку. Повторный `start` не создаёт вторую копию.
`is-active`, `is-enabled`, `list-units` и `list-unit-files` также поддерживаются.
`status`/`is-active` возвращают 0 для active, 3 для остальных состояний.

Рабочий стол получает клавиатуру и экран; консольная оболочка ждёт его закрытия.
После входа в desktop окно Terminal наследует выбранного пользователя. Чтобы отключить автозапуск
рабочего стола, откройте Terminal и выполните `systemctl disable desktop` от root.
По умолчанию службы не имеют авторизованного пользователя. Для системного
демона можно явно задать `User=root`; это применяется до первого выполнения
процесса. Такой unit, `/`, `/etc`, `/etc/services` и `/etc/services/enabled`
должны принадлежать UID 0 и не разрешать запись группе/остальным. Определение
проверяется вместе с чтением под блокировкой пространства имён. Остальные
значения `User=` пока отвергаются. Без `User=` поведение не меняется: например,
автозапущенный desktop показывает экран входа, а не получает root автоматически.

`ext install openssh` устанавливает, включает и запускает `sshd.service` с
`User=root`. Управление — `systemctl status|start|stop|restart sshd`, журнал —
`/var/log/sshd.service`. См. [OpenSSH](openssh.md).

## Своя служба

Создайте `/etc/services/myapp.service`, например редактором `edit`:

```ini
[Unit]
Description=My background program

[Service]
Type=simple
ExecStart=/bin/myapp "argument with spaces"
Restart=on-failure
StandardInput=null
```

Затем:

```sh
systemctl daemon-reload
systemctl enable --now myapp
cat /var/log/myapp.service
```

- `ExecStart`: абсолютный путь к исполняемому файлу и аргументы; кавычки `'`/`"`
  и экранирование обратной косой чертой. Максимум 32 аргумента и 255 байт команды.
  Это не строка оболочки: нет `&`, конвейеров, перенаправлений и подстановок.
  Программа работает на переднем плане собственного процесса, без daemonize/fork.
- `Restart=no` (по умолчанию), `always` или `on-failure`. Ненулевой код выхода,
  включая принудительное завершение, считается сбоем. Между попытками — секунда.
  Явная команда `stop` отменяет перезапуск. Ошибка загрузки ELF/конфигурации
  переводит службу в failed до следующего ручного запуска.
- `StandardInput=null` по умолчанию; `tty` — клавиатура консоли (для desktop).
  stdout и stderr добавляются в `/var/log/ИМЯ.service`; журналы не ротируются.
- `User=root` — явная авторизованная root-личность для доверенной системной службы.
  Если параметр отсутствует, служба запускается без авторизации.
- `Type=simple` — единственный поддерживаемый тип. В `[Service]` неизвестные
  параметры отвергаются, чтобы опечатка не меняла поведение молча.

`daemon-reload` перечитывает определения, добавляет новые и убирает удалённые
неактивные службы. Работающие процессы сохраняются; новый `ExecStart` применяется
при следующем запуске/перезапуске. Перечитывание само по себе не запускает службы.
Включение хранится отдельным файлом `/etc/services/enabled/ИМЯ.service`.

Ограничения: до 16 служб, имя до 27 символов вместе с `.service` (буквы ASCII,
цифры, `_`, `-`), определение до 1024 байт, рабочий каталог `/`. Зависимости
`After`/`Requires`, цели, пользовательские сеансы, готовность сетевых/оконных
служб и запуск GUI-клиентов после готовности desktop пока не реализованы.
Не рассчитывайте на порядок запуска нескольких служб.
Остановка принудительная, по группе процессов; процессы, создавшие отдельную
группу, не отслеживаются. Действуют существующие ограничения учётных записей
MyOS: файловые права проверяются ядром, но полная изоляция остальных интерфейсов
процессов ещё не завершена. См. [права файлов](permissions.md).

Проверка: `make servicetest` собирает и загружает отдельный тестовый диск в QEMU,
проверяет жизненный цикл, перезапуск, аргументы, журналы, права управления,
сохранение enable и автозапуск после повторной загрузки.

## Вход в графическую сессию

При автозапуске desktop служба не имеет авторизованного пользователя и показывает
экран входа. Выберите аккаунт клавишами Up/Down либо стрелками мышью в строке
аккаунта, введите пароль и нажмите Enter или Sign in. Ошибка пароля оставляет
экран входа открытым. Escape закрывает desktop и возвращает консольный вход.
При первом запуске без настроенных аккаунтов предлагается задать и подтвердить
пароль root. Если desktop запущен из авторизованной оболочки, повторный вход
не требуется. Программы рабочего стола наследуют права выбранного пользователя.

Ядро отдаёт экрану входа только публичные имена аккаунтов через
`account_list(name, index)`; пароли и их хеши остаются в ядре.
Проверка в QEMU на временных дисках: `python3 tests/desktop_login_smoke.py`.

В системном меню рабочего стола пункт Log Out закрывает программы сессии,
сбрасывает авторизацию и возвращает экран входа для выбора другого аккаунта.
Close Desktop закрывает графический интерфейс. Tab переключает фокус между
аккаунтом, полем пароля и кнопкой входа; активное поле выделено рамкой,
в поле пароля отображается мигающая каретка.
