# OpenSSH через ext

Порт upstream OpenSSH 10.6p2 собирается штатными `cc` и `make` внутри MyOS.
Установить от root:

```
ext install openssh
systemctl status sshd
```

С хоста: `ssh -p 2222 user@127.0.0.1`, если MyOS запущена с
`make run QEMU_CPU=max SSH_PORT=2222`.

Установка создаёт конфигурацию и Ed25519-ключ хоста, проверяет `sshd -t`,
добавляет `/etc/services/sshd.service` с `User=root`, включает автозапуск и
запускает сервер сразу. При следующей загрузке он стартует до локального входа.
Повторный запуск `/ext/bin/openssh-setup` сохраняет ключи, конфигурацию и
существующее определение службы; работающая служба не дублируется.

```sh
systemctl status sshd
systemctl restart sshd
systemctl stop sshd                # остановить до следующей загрузки
systemctl disable --now sshd       # остановить и отключить автозапуск
systemctl enable --now sshd
cat /var/log/sshd.service
```

`ext uninstall openssh` сначала отключает и останавливает службу, удаляет её
определение и программы; ключи и SSH-конфигурация остаются. Если пакет уже отмечен
как установленный, `ext install` его пропускает: для регистрации службы после
обновления установщика выполните `/ext/bin/openssh-setup` от root.
Ранее запущенный вручную сервер остановите перед первым запуском службы.
Для отладки сначала `systemctl stop sshd`, затем `/ext/bin/sshd -D -e -ddd`,
чтобы два сервера не пытались занять порт 22. Для этой версии нужны обновлённые
ядро (поддержка `User=root`) и пакет OpenSSH. В Live-системе изменения установки
по-прежнему не сохраняются после выключения, если не включены в исходный образ.

В `/ext/bin` устанавливаются `ssh`, `sshd`, `sshd-session`, `sshd-auth`,
`ssh-keygen`, `ssh-keyscan`, `scp`, `sftp`, `sftp-server`, `openssh-setup`.
Настройки находятся в `/etc/ssh`. Для root по умолчанию разрешён вход только
по ключу: публичную часть помещают в `/root/.ssh/authorized_keys`. Пароли
проверяются по базе MyOS в ядре, без передачи хешей пользовательскому процессу.

Для криптографической случайности требуется RDRAND. В QEMU добавьте
`-cpu max` (запуск: `make run QEMU_CPU=max SSH_PORT=2222`); при отсутствии этого источника генерация ключей завершится ошибкой.
Профиль использует встроенную криптографию OpenSSH без OpenSSL и zlib, IPv4,
Ed25519, Curve25519 и ChaCha20-Poly1305/AES-CTR. RSA/ECDSA, PAM, FIDO,
компрессия, IPv6 и агентные Unix-сокеты не включены.

Для повторных обращений к заголовкам добавлен положительный LRU-кэш имён VFS;
удаление, переименование и операции с томом сбрасывают его. Проверка:
`make fslookuptest`.

Стек пользовательского процесса увеличен до 1 МиБ: встроенному компилятору
нужен дополнительный стек для крупных исходников OpenSSH.

В ядре добавлены локальные двусторонние потоки с передачей дескрипторов,
проверка готовности I/O, неблокирующие операции, флаги close-on-exec,
реальные/эффективные/сохранённые UID и GID, chroot и получение энтропии.
POSIX-адаптер находится внутри пакета; старый сетевой ABI MyOS сохранён.
Интерактивная оболочка использует унаследованную от SSH личность и не запрашивает
повторный вход. Явный `logout` сбрасывает её и снова требует авторизацию.
Проверки исполнения upstream используют настоящий `access(X_OK)` с правами MyFS;
формат ELF дополнительно проверяется ядром. Запрос пароля использует текущий терминал процесса вместо
отсутствующего `/dev/tty`, с отключением эха ввода. Сбор дочерних процессов использует waitpid и poll,
поскольку MyOS не доставляет SIGCHLD. PTY передаются как анонимные дескрипторы;
проверки владельца узла `/dev/tty` заменены этим механизмом MyOS.

MyFS защищает файлы владельцами и режимами. Приватным ключам задавайте 0600,
домашним каталогам — 0700; старые порты пересоберите после обновления libc.
См. [миграцию прав](permissions.md). Остальные ограничения профиля сохраняются;
используйте сервер в изолированной тестовой сети. `LoginGraceTime 0` необходим
из-за отсутствия POSIX-таймеров: зависшие соединения до входа занимают слоты
`MaxStartups` до закрытия или перезапуска сервера. SIGHUP не перезагружает
настройки; используйте `systemctl restart sshd`. SFTP поддерживает chmod/chown; изменение времени,
произвольное усечение файлов, statvfs и жёсткие ссылки через SFTP не поддержаны.
Привязка к конкретному IP отклоняется: native bind умеет только все интерфейсы.

`make openssh-build` скачивает исходники, сверяет SHA256 из
[объявления релиза](https://www.openssh.org/txt/release-10.6p2), применяет те же
файлы и патчи и собирает целевые ELF встроенным cc на хосте.
`make opensshtest` использует отдельные загрузочный и файловый образы QEMU.
Подробности профиля также доступны внутри ОС:
`/ext/instructions/openssh/README.txt`.

`make openssh-recipetest` проверяет граф всех 235 исходников настоящим make
MyOS и проверяет, что команды помещаются в лимиты sh/exec.
`make openssh-exttest` собирает порт самим ext в QEMU и затем повторяет
сетевые тесты. Для этой проверки меняется только транспорт: в тестовый
образ заранее кладётся архив с проверенным SHA256, без повторного скачивания.
