# Автоматическая установка пакетов ext

## Выбор пакетов для нового образа

В `.env` на компьютере сборки:

```dotenv
EXT_AUTOINSTALL_PACKAGES="openssh lua"
```

Затем `make usb-image` или `make netboot-image`. Во время сборки пакеты
не скачиваются и не компилируются: образ получает список для установки
**при загрузке MyOS**. Пустое значение по умолчанию оставляет сервис выключенным.
Имена проверяются по `ext/instructions`; строка не исполняется как shell-команда.
Значение можно переопределить переменной окружения или аргументом Make.

`make install` сохраняет существующий `/etc/ext/autoinstall.conf` и состояние
включения сервиса на постоянном диске. Изменение `.env` задаёт начальный список
для нового образа, а не перезаписывает настройки уже установленной системы.

## Управление внутри MyOS

Войдите как root:

```sh
ext auto add openssh lua
ext auto list
ext auto remove lua
ext auto run
ext auto status
```

`add` сохраняет список и включает `ext-autoinstall.service` на следующие загрузки.
Немедленная установка запускается отдельно через `ext auto run`.
Повторное добавление не создаёт дубликатов. Неизвестное имя отклоняется.
`remove` убирает пакет из списка, сохраняя установленную программу;
при пустом списке сервис выключается. Изменять список, устанавливать и удалять
пакеты может только авторизованный root. Просмотр доступен обычным пользователям.

Можно редактировать `/etc/ext/autoinstall.conf` вручную: один пакет на строку,
пустые строки и комментарии `#` разрешены. Файл и его родители должны принадлежать
root и не разрешать запись группе/остальным. При ручном редактировании включение
сервиса выполняется отдельно:

```sh
systemctl enable ext-autoinstall
systemctl start ext-autoinstall
systemctl status ext-autoinstall
```

Для отключения: `systemctl disable ext-autoinstall`. Это не удаляет пакеты.

## Поведение при загрузке

Сервис запускает `/bin/ext auto run --boot` с `User=root`, `StandardInput=null`
и `Restart=no`. Установка идёт в фоне; терминал и другие сервисы продолжают запуск.
Если сетевой адаптер поднят, но ещё не получил IP, ожидание ограничено 30 секундами.
При отсутствии сети локальные рецепты всё равно выполняются. Команда `fetch`
сохраняет существующие ограниченные повторы загрузки; скрипт сборки целиком
автоматически не повторяется в рамках одного запуска.

Установка последовательная, через тот же обработчик, что и `ext install`:
зависимости устанавливаются первыми, успешные пакеты отмечаются в `/ext/installed`.
Уже отмеченные пакеты пропускаются. Автоматического обновления версий нет.
Ошибочный пакет не мешает попытке установки следующих пакетов. При ошибках
сервис завершится с ненулевым кодом и будет показан как `failed`;
бесконечного перезапуска не происходит. Ошибки записи состояния могут остановить пакетную установку.

`ext install`, `ext uninstall`, изменение списка и автоустановка занимают общее
имя `ext-install` в реестре ядра. Второй процесс получает сообщение о занятом
менеджере. Запись освобождается после завершения процесса; lock-файлов нет.

Журналы:

- `/var/log/ext-autoinstall.log` — события и полный вывод установщиков/компиляторов.
- `/var/log/ext-autoinstall.service` — вывод процесса сервиса.
- `/var/lib/ext/autoinstall.status` — последняя попытка: `pending`, `running`,
  `installed`, `skipped`, `failed`; `run incomplete` означает незавершённый запуск.

Конфигурация и снимок состояния записываются во временный файл. Поскольку MyFS
не заменяет существующий файл через `rename`, предыдущая версия временно хранится
рядом с суффиксом `.previous`. Чтение использует её, если процесс был прерван между
переименованиями и основное имя ещё отсутствует.
Это не транзакционный установщик: после ошибки рецепта могут остаться его
рабочие файлы. Запись об успешной установке появляется только при успехе рецепта.

В Live-режиме список из образа применяется при каждом старте, поскольку изменения
корня, включая установленные пакеты, теряются после выключения. На постоянном
корне записи установки сохраняются и пакеты пропускаются. Для OpenSSH обычный
рецепт сам создаёт, включает и запускает `sshd.service`.

## Проверки

```sh
make exttest envtest
python3 tests/ext_auto_config_test.py
make extautotest
```

QEMU-тест использует только временный диск и локальные тестовые рецепты, без сети.
Проверяет автозапуск до входа, зависимости, продолжение после ошибки, повторный
старт с пропуском установленных пакетов, команды управления, блокировку и права.
