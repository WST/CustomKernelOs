# NVIDIA: высокое разрешение через BIOS VBE

Аппаратный live-образ использует видеобиос карты для настройки линейного
framebuffer до перехода в protected mode. Это базовый вывод на NVIDIA с
Legacy VBIOS/VBE, а также на других VBE-совместимых картах. NVIDIA обнаруживается
по PCI vendor 10de на всех шинах, включая карты за PCI-мостами; обнаружение
пишется в журнал. На гибридных системах это не определяет владельца экрана:
вывод остаётся на устройстве, выбранном BIOS.

```sh
make -j4 usb-image                  # EDID preferred, затем Full HD и запасные режимы
make -j4 usb-image USB_VIDEO=1920x1080
make -j4 usb-image USB_VIDEO=2560x1440
```

При загрузке нажми **V** в течение трёх секунд: появится меню разрешений.
Клавиши 0–9 выбирают Auto, 640×480, 800×600, 1024×768, 1280×720,
1280×1024, 1600×900, 1920×1080, 1920×1200 или 2560×1440.
Enter или тайм-аут оставляют значение сборки. Выбор действует один сеанс.
Меню использует клавиатуру BIOS: для USB-клавиатуры может понадобиться
USB Legacy Support в настройках платы.

Исходники драйверов находятся в `drivers/video/`. Начальный модуль NVIDIA
знает GTX 1660 SUPER (10de:21c4), проверяет соответствие framebuffer BAR1
и показывает имя карты в `sysinfo` только при подтверждённом совпадении.

Результат: `build/myos-usb.img`. Запрошенный режим записан в
`build/hardware/manifest.json`. Явный выбор отключает EDID-выбор; если режим
недоступен или BIOS отказывает при установке, загрузчик пробует запасные режимы:
1920×1080, 1920×1200, 1600×900, 1680×1050, 1280×1024, 1280×720,
1024×768, 800×600, 640×480. EDID используется только при корректных заголовке,
контрольной сумме и первом предпочтительном detailed timing.

Поддерживаются только режимы, объявленные BIOS: 32 bpp, RGB 8:8:8,
линейный framebuffer, до 2560×1600 и 16 МиБ с учётом pitch.
У VBE 3.0 используются именно линейные pitch и цветовые маски.
При отсутствии подходящего режима остаётся текстовая консоль.

Подключи монитор к карте перед загрузкой и включи Legacy/CSM.
Чистый UEFI/GOP пока не поддерживается. При успешном запуске runtime VBE
доступно переключение внутри ОС: `mode 1920x1080` или приложение Display.
Список доступных режимов проверяет ядро по реальным данным BIOS; неизвестные
режимы отклоняются без изменения экрана. `/etc/display` применяется при
загрузке, если он явно добавлен в образ; сам live-том остаётся в RAM.
При сборке USB-образа настройки экрана из разработческого `disk.img`
не наследуются: начальный режим определяют меню и параметр `USB_VIDEO`.

Runtime VBE выполняет видеобиос программным интерпретатором x86 с отдельной
копией IVT/BDA, BIOS RAM и ROM. Ядро сохраняет paging, IDT и SMP; вызовы
сериализованы существующей общей блокировкой ядра. Для framebuffer заранее
создаются общие таблицы страниц на 16 МиБ. После смены режима обновляются
pitch, размеры консоли, границы мыши и поколение экрана рабочего стола.
Вызовы ограничены числом инструкций; неизвестные I/O/MMIO отклоняются.
Если инициализация BIOS-интерпретатора не удалась, сохраняется загрузочный
режим, журнал содержит `VBE runtime: unavailable`.
Совместимость с физическим видеобиосом GTX 1660 SUPER ещё не подтверждена.
Рендеринг выполняет CPU с PAT WC, если доступно.
Это не нативный драйвер NVIDIA: нет 3D, CUDA, аппаратного курсора, собственного управления
DisplayPort/HDMI, hotplug, нескольких мониторов и собственных таймингов.
GPU-ускорение GTX 1660 SUPER не реализовано. Для него требуются драйвер
инициализации Turing, управление GPU VM/VRAM, FIFO, каналы copy/2D и fences;
поддержка VBE не предоставляет этих возможностей.
Документация: [NVIDIA hardware interfaces](https://github.com/NVIDIA/open-gpu-doc),
[NVIDIA open kernel modules](https://github.com/NVIDIA/open-gpu-kernel-modules).
BIOS может не предлагать родное разрешение монитора даже на мощной карте.

## Проверка на компьютере

В `dmesg` должны быть `NVIDIA display controller`, `VBE boot: base=` и
`Framebuffer: base=`; `sysinfo` покажет `NVIDIA 1660 SUPER VBE` при совпадении BAR1
или общий `BIOS VBE framebuffer`, а также фактический режим.
Проверь читаемость консоли после прокрутки, рабочий стол и движение курсора.
Если экран не появился, собери образ с `USB_VIDEO=1024x768` и сообщи модель
карты, PCI device ID, версию BIOS, подключение монитора и журнал загрузки.

Автоматическая проверка: `make videoruntimetest` проверяет смену физических
режимов из работающей ОС, повторные переходы, пиксели консоли, отказ для
неизвестного режима, изменение размеров работающего desktop и два CPU.
`make videotest` проверяет меню, EDID, Full HD,
1440p, fallback при нехватке VRAM и модуль NVIDIA с моделируемым PCI.
`make usbtest` проверяет VBE, консоль, desktop,
запасной текстовый путь и прежний VMware backend в QEMU. Она не подтверждает
работу физической NVIDIA; её нужно проверить отдельно на целевой карте.

Формат VBE: [VESA VBE Core 3.0](https://pdos.csail.mit.edu/6.828/2011/readings/hardware/vbe3.pdf).

## Отказ `blocked access e000 type=402`

`type=402` — OUT DWORD (32-битная запись в порт). Видеобиос GTX 1660 SUPER
может использовать BAR5: отдельное I/O-окно косвенного доступа к GPU.
Исправление читает адрес BAR5 из PCI и разрешает его 128-байтный диапазон
для карты 10de:21c4, при этом I/O decode должен быть
включён, адрес выровнен и помещается в 16-битное пространство портов.
PCI-регистры не перенастраиваются; при другом назначении портов (например,
0xc000 вместо 0xe000) действует тот же механизм. Выход за границы отклоняется.
Проверка: `make nvidia-iotest`; тест вызывает настоящий callback VBE
с `port=0xe000, type=0x402`, подменяя только физический доступ к портам.

В `dmesg | grep VBE` должна появиться строка `NVIDIA BAR5 I/O ...`, затем
число доступных режимов или точная причина следующего отказа. Работа этого
исправления на физической карте ещё требует проверки.
Описание интерфейса: [Envytools BAR5](https://envytools.readthedocs.io/en/latest/hw/bus/bars.html).

### Framebuffer со смещением или в другой апертуре

На физическом ПК с TU116 зафиксирован `framebuffer=0xf1000000`, при этом
проверка равенства framebuffer началу BAR1 не проходила. Из-за этого предыдущий
вариант ошибочно не включал разрешение BAR5. Теперь I/O-окно проверяется
независимо: vendor/device/class PCI, тип и диапазон BAR5, включённый I/O decode.
Не требуется определять размер BAR1 или менять PCI-регистры активной карты.
Атрибуция имени framebuffer через BAR1 остаётся консервативной и не управляет
доступом к I/O. В журнал добавлены BAR1, BAR3, BAR5, command и адрес framebuffer.
Тест `make nvidia-iotest` включает этот сценарий и перенос BAR1 выше 4 ГиБ
при независимом, корректном 16-битном BAR5.

## Четыре доступных режима после исправления BAR5

На реальной GTX 1660 SUPER BIOS-интерпретатор успешно получил четыре
принимаемых 32-битных режима: 640×480, 800×600, 1024×768, 1280×1024.
Это подтверждает перечисление режимов, но не работу GPU-ускорения и не
выполнение реального переключения, если выбран уже текущий режим.

Для различения ограничений BIOS и фильтров драйвера добавлен аудит:
`dmesg | grep VBE` показывает принятые режимы, причины отказа для больших
режимов, полноту списка и наибольший размер, возвращённый BIOS. Причины:
глубина не 32 bpp, отсутствующий LFB, не direct color, маски не RGB 8:8:8,
ограничение размеров/pitch/адреса framebuffer. В строке `VBE audit` есть
счётчики всех причин; подробные отказы ограничены 24 строками.
После фактической смены BIOS-режима печатается `VBE runtime: switched ...`.

Нельзя сделать 1920×1080 доступным простым включением кнопки в Display.
Если BIOS его не предлагает, нужен отдельный нативный modesetting-драйвер
NVIDIA. Если он возвращается только в другом формате пикселей, потребуется
добавить соответствующий framebuffer backend. Текущий backend требует 32 bpp.
