# Параллельная сборка внутри MyOS

Наш `make` поддерживает параллельное выполнение независимых целей:

```sh
make -j4
make -j 2
make --jobs=4
make -j
```

Без `-j` остаётся одна задача. `-j` без числа или `-j auto` выбирает минимум
из фактически запущенных CPU и оценки свободной RAM: 64 МиБ на задачу,
с нижней границей 1 и верхней 16. Это оценка, не гарантированный размер
компилятора. Явное число 1..16 задаёт собственный предел.

Планировщик сначала строит граф целей. Общая зависимость выполняется один раз;
цель запускается после успешного завершения всех её зависимостей. Строки одного
рецепта остаются последовательными. При ошибке новые задачи не запускаются,
уже запущенные рецепты завершаются и собираются через waitpid, затем make
возвращает ошибку. `-n` выводит команды без выполнения.

## EXT

```sh
ext install nano
ext install -j4 openssh
ext install -j1 lua
```

EXT автоматически передаёт make число задач. Зависимые пакеты, загрузка,
распаковка и установка выполняются в прежнем порядке; параллельна именно
сборка независимых целей. Отметка установки появляется после завершения make.
Прямые команды `cc` в setup.inst остаются последовательными; Lua переведён
на Makefile, Nano/OpenSSH/Bash уже используют Makefile.

В `.env` компьютера сборки:

```dotenv
EXT_BUILD_JOBS=auto
```

Допустимы `auto` или 1..16. При сборке нового образа значение попадает в
`/etc/ext/build-jobs`. Существующая настройка постоянного диска сохраняется.
Внутри MyOS её можно изменить командой:

```sh
echo 4 > /etc/ext/build-jobs
```

Приоритет: `ext install -jN` → явный `make -jN` в рецепте → файл настройки → auto.
Автоустановка EXT при загрузке использует тот же файл. Для одного файла исходника
несколько CPU не ускорят компиляцию: параллелизм возникает между отдельными
объектами/целями. Рекурсивного GNU jobserver пока нет; вложенный make без `-j`
последователен. Подмножество синтаксиса Makefile и прежняя проверка актуальности
по существованию файла/пересобранным зависимостям сохраняются.

Lua сначала собирает объекты и архив liblua.a, затем линкует интерпретатор.
Команды разделены так, чтобы укладываться в ограничение shell на длину строки.

## Проверки

`make maketest` проверяет последовательный режим, перекрытие задач при -j2/-j4,
общие зависимости, порядок, пределы, ошибки и ожидание незавершённых задач.
`make parallel-buildtest` на отдельном диске QEMU с 4 CPU компилирует настоящие
C-файлы, проверяет перекрытие интервалов и APIC ID компиляторов, -j1, настройку
из файла и установку настоящих Nano и Lua. Нужны заранее загруженный архив Nano,
подготовленный `make nano-build`, и исходники Lua 5.4.8 из `make luatest`. Пользовательский disk.img не изменяется.
