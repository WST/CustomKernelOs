# Настройки окружения

Общие пользовательские настройки находятся в `.env` в корне репозитория.
Пример всех поддерживаемых параметров — `.env.example`. Локальный `.env`
игнорируется Git; пример входит в репозиторий.

При первоначальной настройке, если `.env` ещё нет:

```sh
cp .env.example .env
```

В PowerShell: `Copy-Item .env.example .env`.
Укажите LAN-адрес сервера в `NETBOOT_URL`. Пример:

```dotenv
USB_ROOT_MB=256
USB_VIDEO=auto
NETBOOT_BIND=0.0.0.0
NETBOOT_PORT=8080
NETBOOT_URL=http://192.168.1.10:8080/boot.ipxe
IPXE_JOBS=4
```

После этого параметры не нужно повторять в командах:

```sh
make netboot-image
make netboot-usb
make netboot-serve
```

В Windows сервер читает тот же файл без Make/WSL:

```powershell
py tools/netboot.py serve
```

Настройки перечитываются при новом запуске команды. Для изменения адреса/порта
уже запущенного сервера его нужно перезапустить. При изменении `NETBOOT_URL`
нужно пересобрать и заново записать одноразовый iPXE-USB. Для обновлений самой
MyOS достаточно `make netboot-image` и перезагрузки тестового компьютера.

## Приоритет

1. Аргументы команды: `make usb-image USB_ROOT_MB=512` или Python `--root-mb 512`.
2. Уже заданные переменные окружения процесса.
3. `.env`.
4. Встроенные значения по умолчанию, если `.env` отсутствует.

Make экспортирует настройки дочерним процессам и рекурсивным сборкам. Например,
переопределение `USB_ROOT_MB=512` не сбрасывается при вызове Python-сборщика.
Чтение `.env` выполняется общим `tools/env_config.py`, без `source`, `eval` или
исполнения Make/shell-команд из файла. Разрешены `NAME=value`, необязательный
префикс `export`, пустые значения, одинарные/двойные кавычки и комментарии.
Значения буквальные: подстановки `${VAR}`, shell-команды и escape-последовательности
не вычисляются. Windows-пути с обратными слешами сохраняются. Поддерживаются
UTF-8, BOM и CRLF. Неизвестный ключ или неверные кавычки дают явную ошибку.

## Параметры

| Настройки | Назначение |
|---|---|
| `DISK`, `DISK_MB`, `DATA_DISK` | Основной MyFS-образ, размер нового образа и дополнительный диск QEMU |
| `QEMU_MEM`, `QEMU_CPUS`, `QEMU_CPU` | RAM, процессоры и модель CPU эмулятора |
| `VGA`, `GPU`, `QEMU` | Видеокарта, режим ускорения и исполняемый файл QEMU |
| `HOST_PORT`, `SSH_PORT` | Проброс гостевых HTTP/SSH-портов на хост |
| `USB_ROOT_MB`, `USB_VIDEO` | Размер Live-корня и режим BIOS-видео |
| `NETBOOT_BIND`, `NETBOOT_PORT` | Интерфейс и TCP-порт HTTP-сервера |
| `NETBOOT_URL` | Полный адрес `/boot.ipxe`, записываемый в iPXE-загрузчик |
| `NETBOOT_DIRECTORY` | Каталог опубликованных образов и `latest.json` |
| `NETBOOT_IMAGE`, `NETBOOT_MANIFEST` | Исходный Live-образ и manifest для публикации |
| `IPXE_JOBS` | Число параллельных задач сборки iPXE |
| `CROSS`, `CC`, `LD`, `AR`, `NM`, `OBJCOPY`, `NASM`, `HOSTCC` | Кросс-префикс и инструменты сборки |

Относительные пути Python-инструментов считаются от корня проекта. Для настройки
общей Windows/WSL-сборки предпочтительны относительные пути.
`DISK_MB` не расширяет существующий диск. `USB_ROOT_MB` остаётся ограниченным
64–512 МиБ. `NETBOOT_URL` — публичный адрес, он не подставляется автоматически
из `NETBOOT_BIND`: при изменении порта проверьте оба параметра. В примере
`HOST_PORT=8081` отделён от `NETBOOT_PORT=8080`, чтобы QEMU и netboot могли
работать одновременно. `QEMU_CPU=max` нужен для RDRAND при SSH, а
`SSH_PORT=2222` включает проброс SSH.

Внутренние списки объектов, ABI-константы и закреплённый commit iPXE не являются
пользовательскими настройками и остаются в коде.

Проверка: `make envtest netboottest`; в Windows — `py tests/env_config_test.py`.

## Сборка пакетов в гостевой ОС

`EXT_BUILD_JOBS=auto` задаёт начальную настройку `/etc/ext/build-jobs`: auto либо
1..16. Автоматический режим учитывает запущенные CPU и свободную RAM.
Существующий файл сохраняется при обновлении постоянного диска.
Подробности: [parallel-build.md](parallel-build.md).
