# Code

Запуск: `code /папка` открывает рабочую папку, `code /папка/main.c` — файл
и содержащую его папку. Без аргументов используется текущая папка.

- Номера строк, UTF-8, выделение мышью и Shift со стрелками, общий буфер обмена.
- Тёмная подсветка: ключевые слова, типы, функции, числа, строки, комментарии
  и директивы препроцессора. Новый документ по умолчанию считается C-кодом.
  Поддержаны `.c`, `.h`, `.cpp`, `.hpp`, `.js`, `.ts`, `.json`, `.py`.
- Explorer слева: щелчок раскрывает папку или открывает файл; `^` и `v`
  прокручивают дерево. **File → Open Folder** или поле папки в центре верхней панели позволяют ввести путь рабочей папки.
  Enter подтверждает, Esc отменяет. Относительные имена новых файлов
  разрешаются от рабочей папки. Одновременно видны до 256 узлов дерева.
- После двух символов появляются до шести подсказок: ключевые слова,
  API из `/include` и имена из текущего документа. Стрелки выбирают вариант,
  Tab вставляет, Esc скрывает. Подсказка API показывает объявление и заголовок.
- Заголовки тоже дополняются: `#include <wi` → Tab → `#include <win.h>`.
- Enter сохраняет отступ и добавляет четыре пробела после `{` или `:`.
  При вставке из буфера автоматические отступы отключены.
- Ctrl+S — сохранить, Ctrl+O — поле пути, Ctrl+N — новый документ.
- Ctrl+A/C/X/V — выделить всё, копировать, вырезать, вставить.
- **Build / Ctrl+B** сохраняет `.c` и запускает внутренний `/bin/cc` с рабочей
  папкой в `-I`. Результат — файл рядом с исходником без `.c`. Строка состояния
  показывает результат; диагностика — в `/tmp/code-build-PID.log`.

Индекс C API строится из установленных заголовков `/include`, включая
`myos.h`, `gfx.h`, `win.h` и стандартные C-заголовки. Он содержит до 1024 имён
и обновляется при перезапуске редактора. Компилятор автоматически использует
`/include` и библиотеки `/lib/libc.c`, `gfx.c`, `vec.c`, `font.c`, `win.c`.
Например, подключите `#include "win.h"`, используйте `win_create`, `gfx_text`,
`win_event`, и нажмите Build. Кнопка собирает один C-файл; несколько исходников
можно собрать командой `cc file1.c file2.c -o program` в терминале.

Подсветка лексическая. Автодополнение работает без LSP, анализа типов выражений
и членов структур. Лимит загрузки — 4000 строк и менее 2 МиБ. Длинные строки
не обрезаются; двоичные и слишком большие файлы отклоняются с сохранением
текущего документа. Табуляции превращаются в четыре пробела, переводы строк —
LF; непустая последняя строка завершается LF, как в исходном Блокноте.

Перед заменой несохранённого документа требуется повторная команда
Ctrl+N/Ctrl+O или повторный щелчок по выбранному файлу. Закрытие без сохранения
также требует повторного нажатия X.

Проверка: `make codetest` и `python3 tests/code_gui_smoke.py`.
GUI-проверка создаёт отдельный образ в `build/code-gui-smoke`, загружает ОС
в QEMU, сохраняет скриншоты и проверяет раскрытие папки, редактирование
вложенного файла, автодополнение C API, сохранение и внутреннюю сборку.

Верхняя часть редактора оформлена в тёмной теме: меню File/Edit/View/Run,
поле рабочей папки, вкладка активного файла с отметкой изменений и строка пути.
Ввод пути открывается во всплывающем поле; Enter подтверждает, Esc отменяет.
Вкладка отображает один текущий документ; её крестик закрывает его с тем же
предупреждением о несохранённых изменениях, что и Ctrl+N.

Подсказка аргументов появляется внутри вызова и остаётся после запятой.
Текущий параметр выделяется; вложенные вызовы, скобки, строки и комментарии
учитываются при подсчёте аргументов. Доступны объявления из системных заголовков
и простые объявления функций в текущем файле. Esc скрывает подсказку.
Скобки и кавычки вставляются парами, закрывающий символ можно пройти повторным
вводом, Backspace удаляет пустую пару. В строках, комментариях и при вставке
из буфера автоматические скобки отключены. Home переключает начало кода
после отступа и начало строки. Текущая строка выделяется фоном.
