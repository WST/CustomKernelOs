# Постоянное хранилище и восстановление MyFS

В обычной системе MyFS пишет на ATA/AHCI-диск. В Live-системе с xHCI и USB
Mass Storage Bulk-Only/SCSI корень теперь находится на загрузочной флешке.
Пароль, настройки и файлы сохраняются между загрузками. Сообщения
`USB persistent root:` и `USB boot disk (persistent)` подтверждают этот режим.

Загрузчик передаёт ядру случайный ID диска и границы корневого раздела.
Драйвер проверяет MBR и ёмкость носителя; запись разрешена только внутри этого
раздела. Внутренние ATA/AHCI-диски в Live по-прежнему скрыты. Две флешки с
одинаковым ID при первоначальном обнаружении считаются неоднозначными.
После извлечения носителя операции возвращают ошибку; подмена накопителя и
переключение на RAM не выполняются.

На неподдерживаемом контроллере, UAS-устройстве, носителе с сектором другого
размера или при netboot без соответствующей флешки остаётся RAM-корень.
Ядро явно выводит предупреждение `changes are VOLATILE`. Сейчас поддержаны
первый xHCI-контроллер, BOT, LUN 0 и сектор 512 байт. Проверка на физическом
железе остаётся необходимой; автоматические интеграционные тесты используют QEMU.

## Запись и аварийное отключение

MyFS v4 резервирует в конце тома 121 сектор: commit-запись и до 120 секторов
журнала. В журнал попадают и данные, и метаданные. Каждая транзакция проходит:

1. Запись содержимого журнала и аппаратный сброс кэша.
2. Запись commit-записи с адресами секторов и CRC32, затем сброс кэша.
3. Копирование секторов на основные места и сброс кэша.
4. Очистка commit-записи и сброс кэша.

ATA использует FLUSH CACHE, AHCI — FLUSH CACHE EXT, USB — SYNCHRONIZE CACHE(10).
Хостовая утилита выполняет `fflush` и `fsync` файла образа. Ошибки доходят до
вызывающей программы. После неопределённого результата аппаратной записи том
блокирует дальнейшие изменения до повторного монтирования и восстановления.

Успешный `write` означает, что возвращённое количество байтов зафиксировано.
Большие записи разбиваются на порции до 16 КиБ: при аварии сохраняется
зафиксированный префикс. Создание с правами, создание ссылки, переименование
и удаление записи каталога фиксируются одной транзакцией. Освобождение bitmap
после удаления ссылок выполняется отдельными ограниченными транзакциями;
авария между ними может оставить занятые блоки, которые освобождает проверка
при следующем монтировании. Размер удаляемого файла не ограничен размером журнала.

Это гарантия транзакций файловой системы: последовательность `truncate`,
нескольких `write` и `close` не становится одной атомарной операцией сохранения
всего документа. При заполнении диска возможен короткий `write`; приложение
должно проверять число записанных байтов и результат `close`/`fsync`.
Гарантия предполагает атомарную запись сектора и корректное выполнение FLUSH
накопителем и гипервизором. Повреждения данных вне незавершённого журнала
не исправляются автоматически.

Доступны `sync` и `fsync(fd)`. `fsync` возвращает `-1` и устанавливает `errno`,
`sync` возвращает отрицательный код ошибки. `fsync` сейчас синхронизирует все
смонтированные тома. Штатные выключение и перезагрузка сначала выполняют
синхронизацию и возвращают ошибку при её неудаче. Адаптер OpenSSH также
использует настоящий `fsync`.

## Монтирование и umount

Пример `/etc/fstab`, который читается до загрузки сохранённых настроек экрана
и запуска служб:

```text
# DEVICE      DIRECTORY  TYPE  OPTIONS          DUMP PASS
/dev/sdc1     /home      myfs  defaults         0    0
/dev/sdc2     /mnt/data  myfs  defaults,nofail  0    0
```

Каталоги и файловые системы должны быть созданы заранее. Поддержаны `defaults`,
`rw`, `auto`, `noauto`, `nofail`; поля DUMP/PASS допускаются, но не используются.
Строки обрабатываются по порядку, включая вложенные точки монтирования.
Неизвестные типы и параметры возвращают ошибку. `nofail` разрешает отсутствие
дополнительного диска. `fstab` должен принадлежать root, не быть доступным
для записи группе/остальным и занимать не более 4096 байтов.

```sh
mount /dev/sdc1 /mnt
sync
umount /mnt
# Или:
umount /dev/sdc1
```

`umount` требует root. Корень системы, открытые файлы, cwd или корень файловой
изоляции любого живого процесса, а также вложенные монтирования дают `EBUSY`.
Том отсоединяется только после успешной синхронизации. Кэш имён очищается,
следующее монтирование видит сохранённые файлы.

## Проверка и миграция

При каждом монтировании сначала воспроизводится подтверждённый журнал.
До первой записи восстановления проверяются его CRC32, размеры и адреса.
Затем проверяются типы inode, деревья указателей, уникальность владения
блоками, таблицы прав и дерево каталогов, включая `.` и `..`.
Bitmap восстанавливается по ссылкам; недостижимые inode и открытые на момент
аварии удалённые файлы освобождаются. Эти исправления также журналируются.
Повторная авария во время восстановления допускает повторное воспроизведение.
Неоднозначное владение, повреждённые указатели, каталоги или журнал дают ошибку
монтирования, без попытки угадать и удалить пользовательские данные.

```sh
umount /mnt
fsck /dev/sdc1
mount /dev/sdc1 /mnt
```

На хосте: `build/myfs image.img fsck`. Команда использует ту же проверку и
восстановление при монтировании. Образ должен быть отключён от QEMU.

Тома v1–v3 мигрируют в v4 при монтировании с сохранением прежней раскладки
inode, каталогов и прав. Перед резервированием журнала проверяются реальные
ссылки на блоки; весь хвост из 121 сектора должен быть свободен. Если он занят,
монтирование отказывает без перезаписи данных. Старые ядра/утилиты не должны
использоваться для записи в v4. Форматирование и первоначальное создание
нового образа не являются атомарными относительно выключения питания.

## Проверки

```sh
make persistence-test
make test permissionstest
make persistence-usb-smoke USB_ROOT_MB=64
python3 tests/persistence_lifecycle_smoke.py
```

Хостовый тест перебирает отключения после каждой секторной записи и барьера,
используя три модели кэша: немедленная запись, полностью отложенная и частичная
запись до FLUSH. Проверяются изменение/дописывание файла, каталог, перенос
каталога, удаление, усечение, права, символическая ссылка, многочастное
сохранение, сбой при replay, повреждение журнала/bitmap и ошибки I/O.

USB-тест использует временную копию образа: создаёт пароль и файл, выполняет
SIGKILL QEMU и повторно загружает тот же носитель. AHCI-тест проверяет `fstab`,
открытые дескрипторы, cwd родителя и ребёнка, вложенные тома, `fsync`, `umount`
по имени устройства, повторное монтирование и `fsck`. Исходные `disk.img` и
USB-образ во время этих smoke-тестов не изменяются.
