# Владельцы и права файлов

MyFS хранит UID владельца, GID группы и режим доступа. Ядро проверяет их при
обходе путей, открытии файлов, запуске ELF, создании, удалении и переименовании.
Проверки выполняются заново и при попадании в кэш имён VFS.

## Команды

```
stat secret.txt
ls -l .
chmod 600 secret.txt
chmod 700 private
chown alice:alice secret.txt
chown 1:1 secret.txt
umask 077
```

`chmod` принимает восьмеричный режим и несколько путей. `chown` принимает имя
учётной записи или числовой UID, необязательную группу после двоеточия и несколько
путей. Имена групп соответствуют основным группам аккаунтов: GID равен UID.
Без `:GROUP` группа сохраняется. Рекурсивные и символьные формы команд не добавлены.
`ls -l` и `stat` показывают числовые UID/GID. `umask` — встроенная команда sh;
без аргумента показывает текущую маску, с аргументом меняет маску оболочки.

Три набора `rwx` относятся к владельцу, основной группе и остальным. У каталогов
`x` разрешает проход по пути, `r` — перечисление имён, `w` вместе с `x` — изменение
записей. Для удаления важны права родительского каталога. Sticky-bit (`chmod 1777`)
дополнительно разрешает удаление/переименование только владельцу записи,
владельцу каталога или root. Символическая ссылка сама не ограничивает доступ:
при открытии проверяется цель и весь путь к ней; unlink удаляет саму ссылку.

Root обходит проверки чтения/записи; для запуска обычного файла нужен хотя бы
один execute-бит. Формат ELF проверяется отдельно. Изменять режим может владелец
или root; передавать владение другому UID может root. Владелец может оставить GID
или сменить его на свою основную группу. Setuid/setgid-флаги chmod отклоняются:
повышение привилегий при exec не реализовано. Дополнительных групп и ACL нет. Времена файлов пока не сохраняются.

Новые файлы получают запрошенный режим (обычно 0666), каталоги — 0777, с учётом
umask. Начальная маска процесса 0022; fork/spawn наследуют её, exec сохраняет.
`open(path, flags)` и `mkdir(path)` прежнего native API поддерживаются, а POSIX-вызовы
с явным режимом учитывают этот режим. `access` проверяет реальные UID/GID;
обычные операции используют эффективные UID/GID. Неавторизованный пользовательский
процесс имеет для файловых проверок UID/GID 65534, а не права root.

Открытый дескриптор сохраняет доступ после chmod/chown или смены UID; это относится
к dup, fork и передаче дескрипторов. После unlink inode открытого файла удерживается
до закрытия последней ссылки и последующей уборки, поэтому его нельзя повторно
выдать под чужие данные. Оставшиеся после перезагрузки orphan-inode освобождаются
при монтировании. Во время чтения ELF защищено и соответствие имени/inode.

## Системные каталоги и утилиты

`make install` задаёт /root режим 0700 и /tmp — 1777; существующим
Ed25519-ключу хоста SSH и /root/.ssh/id_ed25519 — root:root и 0600. Вход и создание аккаунта
назначают домашнему каталогу его UID/GID и 0700. /etc/accounts имеет 0600 и остаётся
дополнительно закрытым для прямых пользовательских операций даже root; ядро
обслуживает базу через собственный ограниченный контекст, без изменения UID процесса.

Компилятор создаёт исполняемые ELF с 0755, объектные файлы — с 0644. `cp` учитывает
режим источника и umask. `tar` сохраняет обычные rwx-биты; новые каталоги закрыты
режимом 0700 во время распаковки, затем получают архивные режимы с учётом umask
в порядке от вложенных к родительским. Режимы уже существовавших каталогов не меняются.
Установщик OpenSSH назначает ключу хоста root:root и 0600; SFTP использует настоящие
chmod/chown. После обновления ядра/libc следует пересобрать ранее установленные порты.

## Старые образы и формат

Новые тома имеют MyFS v3. Сохраняются прежние 64-байтовые inode и раскладка данных;
атрибуты находятся в отдельной разреженной таблице блоков, отмеченных в bitmap.
Читаются исходные MyFS v1/v2. Первое изменение атрибутов или создание файла
обновляет суперблок до v3, сохраняя исходную раскладку каталогов и блоков файла.
Необходимы свободные блоки для таблицы. Старые ядра, не знающие v3, отвергают том.

Для старого inode без записи атрибутов: root:root, каталог 0755, ELF 0755,
обычный файл 0644, ссылка 0777. Это совместимые начальные значения, а не восстановление
прежнего владельца: раньше он не сохранялся. Администратору нужно назначить владельцев
старым пользовательским файлам и закрыть секреты, например:

```
chown alice:alice /home/alice/notes.txt
chmod 600 /home/alice/notes.txt
chmod 600 /root/.ssh/id_ed25519
```

`myfs grow` сохраняет владельцев и режимы, включая корень и символические ссылки.
Офлайн-инструмент поддерживает `myfs IMAGE stat PATH`, `chmod OCTAL PATH` и
`chown UID GID PATH`. Существующий рабочий disk.img при разработке не менялся:
проверки выполняются на отдельных образах.

## Проверки

`make permissionstest` проверяет DAC, группы, sticky-bit, ссылки, повторное
использование inode, remount и grow на новых и исходных v1/v2 образах.
`make permissions-smoke` проверяет реальные системные вызовы в QEMU: владельцев,
различие real/effective UID, отказ чтения/усечения/смены владельца, наследованные FD,
unlink открытого файла, umask через fork/exec, запуск ELF, cp/tar, обычный вход,
смену пароля и сохранение после перезагрузки. `make opensshtest` проверяет SSH/SFTP
с настоящими режимами файлов. Файловые права не означают полной изоляции остальных
интерфейсов ОС и не добавляют журналирование при сбоях питания.
