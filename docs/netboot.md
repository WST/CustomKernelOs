# Обновление MyOS по сети: iPXE + HTTP

Один раз запишите маленький iPXE-загрузчик на отдельную тестовую флешку.
Дальше она остаётся в тестовом ПК: при каждом запуске загрузчик получает
актуальный Live-образ с компьютера разработчика. Пересобирать и переставлять
флешку для обновления ядра больше не требуется. Можно также использовать
существующую PXE/iPXE-загрузку без флешки.

Это BIOS/Legacy/CSM-путь. UEFI-only и Secure Boot текущий загрузчик MyOS
не поддерживает. Нужны проводная сеть, DHCP и поддерживаемая iPXE сетевая карта.
Поддержка карты в iPXE и поддержка сети уже внутри MyOS — отдельные вещи.

## Первая настройка

Настройки берутся из общего [`.env`](environment.md). Создайте его по
`.env.example` и задайте `NETBOOT_URL=http://192.168.1.10:8080/boot.ipxe`
с адресом своего ПК, `NETBOOT_PORT=8080` и нужный `USB_ROOT_MB`.
После этого достаточно `make netboot-image`, `make netboot-usb` и
`py tools/netboot.py serve` в Windows либо `make netboot-serve` в Linux/WSL.
Аргументы ниже показывают явные переопределения тех же настроек.

В Linux/WSL из корня проекта:

```sh
make netboot-image
make netboot-usb NETBOOT_URL=http://192.168.1.10:8080/boot.ipxe
```

Замените `192.168.1.10` на LAN IPv4 компьютера, который будет раздавать образы.
Адрес записывается в USB-загрузчик: желательно закрепить его DHCP reservation
на роутере. При изменении адреса сервера загрузчик нужно пересобрать и записать
ещё раз. Изменение содержимого MyOS этого не требует.

`netboot-image` собирает обычный `build/myos-usb.img`, проверяет его SHA-256
по manifest и публикует копию в `build/netboot/images/<sha256>.img`.
Размер корня и режим видео задаются прежними параметрами:

```sh
make netboot-image USB_ROOT_MB=512 USB_VIDEO=1280x720
```

`netboot-usb` скачивает закреплённый Git commit официального iPXE в
`build/ipxe-src`, собирает i386/BIOS-вариант с встроенным сценарием DHCP/HTTP и создаёт
**`build/myos-netboot-usb.img`**. Это маленький загрузочный образ, а не полный
Live-образ. Для сборки нужны git, gcc, binutils, make, perl и заголовки liblzma
(`liblzma-dev` в Debian/Ubuntu, `xz-devel` в соответствующих дистрибутивах).
Revision, URL сервера и хеш результата находятся в
`build/netboot-bootstrap/manifest.json`.

Запишите `myos-netboot-usb.img` на отдельную тестовую флешку в raw/DD-режиме
средством записи образов. Это заменяет содержимое выбранной флешки; скрипты
проекта сами ничего на физические устройства не записывают. Выберите её в
BIOS boot menu и оставьте вставленной. При недоступном сервере iPXE покажет
сообщение и предложит повторить попытку клавишей.

## HTTP-сервер

На Windows удобнее запускать Python непосредственно в Windows, чтобы не
зависеть от проброса портов WSL2. В PowerShell из корня проекта:

```powershell
py tools/netboot.py serve --bind 0.0.0.0 --port 8080
```

На Linux/WSL:

```sh
make netboot-serve NETBOOT_BIND=0.0.0.0 NETBOOT_PORT=8080
```

Для Windows Firewall при необходимости разрешите входящий TCP 8080 для своей
локальной сети. Проброс портов на роутере не нужен. Проверка с другого ПК:
`http://192.168.1.10:8080/boot.ipxe`. Остановка сервера — Ctrl+C.

Сервер раздаёт только `/boot.ipxe`, `/latest.json` и опубликованные образы
`/images/<sha256>.img`, поддерживает HEAD и одиночные HTTP Range-запросы
(206/416), нужные секторному чтению iPXE. Он не раздаёт весь репозиторий,
списки каталогов и произвольные файлы, не принимает загрузку файлов.
TCP_NODELAY устраняет задержки мелких секторных ответов.

HTTP-путь предназначен для доверенной локальной сети. SHA-256 проверяет
целостность публикации на сервере; это не подпись и не аутентификация образа
на загружаемом ПК. Опубликованный Live-образ доступен клиентам сервера целиком.

## Следующие обновления

Оставьте сервер запущенным. После изменения ядра или программ:

```sh
make netboot-image
```

В PowerShell ту же сборку можно вызвать `wsl make netboot-image`.
Перезагрузите тестовый ПК — он возьмёт новую публикацию. Сервер перезапускать
не нужно; физическую флешку не трогайте.

Публикация атомарно переключает `latest.json` только после полной записи и
проверки образа. Сценарий привязывает конкретную загрузку к неизменяемому URL
с хешем. Уже начатая загрузка дочитывает прежний образ даже при публикации
новой версии. Старые образы сохраняются и занимают место на компьютере
разработчика. Удаляйте ненужные версии только когда никто не загружается;
текущий образ определяется `latest.json`.

ОС работает с прежним RAM-корнем: сетевой сервер требуется во время загрузки,
а не для обычных файловых операций после неё. Изменения внутри Live-системы
по-прежнему теряются после выключения. Это не установка на диск и не обновление
ядра без перезагрузки.

## Если iPXE уже есть

В его командной строке:

```text
dhcp
chain http://192.168.1.10:8080/boot.ipxe
```

Сценарий вызывает `sanboot --no-describe` с относительным URL выбранного образа.
iPXE предоставляет нашему существующему загрузчику BIOS INT 13h диск по HTTP;
загрузчик читает ядро и корень так же, как с USB. Отдельный сетевой стек в
загрузчике MyOS для этого не нужен.

## Проверки

```sh
make netboottest
make netbootsmoke
make netboot-usb-smoke   # после первой сборки netboot-usb
```

HTTP-тесты проверяют диапазоны, HEAD, отказ произвольных путей и симлинков,
проверку хеша и переключение публикаций с сохранением старого URL. Работают
также в Windows: `py tests/netboot_test.py`.

`netbootsmoke` загружает QEMU через сетевой iPXE ROM вообще без дисков,
проверяет RAM-корень, первоначальный вход и `whoami`.
`netboot-usb-smoke` собирает тестовый iPXE-USB с loopback-адресом сервера,
загружает его как USB и получает полный Live-образ по сети. Готовый пользовательский
`myos-netboot-usb.img` при этом не перезаписывается. Работа на физической
сетевой карте и настройки BIOS требуют отдельной проверки на целевом ПК.
