# Просмотр оборудования

Команды собираются вместе с ОС и устанавливаются в `/bin`; EXT для них не нужен.
После обновления ядра и пользовательских программ:

```sh
lspci
lspci -nn -v
lsusb
lsusb -t
lsports
lsblk
```

`lspci` перечисляет PCI-устройства на всех 256 шинах и функциях 0–7, включая
устройства за PCI-мостами. Адрес `01:03.1` означает шину 1, устройство 3,
функцию 1. Показываются класс, числовые vendor/device ID, известный производитель
и ревизия; `-v` добавляет programming interface, subsystem ID, IRQ и исходные BAR.
Числовые ID выводятся всегда, `-n`/`-nn` допускаются для удобства. Запись в BAR для
определения размера ресурсов не выполняется. Доступ идёт через legacy CF8/CFC,
только PCI segment 0; расширенное пространство PCIe/ECAM не поддерживается.
Отображение устройства не означает наличие рабочего драйвера.

`lsusb` показывает текущие устройства единственного обслуживаемого
xHCI-контроллера, включая дочерние устройства USB2-хабов. `lsusb -t` добавляет
пустые корневые порты. Пути `5.3.1` означают корневой порт 5, порт 3 первого
хаба и порт 1 следующего хаба. VID/PID обновляются после переподключения;
отключённые устройства удаляются. Slot ID может использоваться повторно,
а generation в программном интерфейсе меняется при новой энумерации.

Состояние корневого подключения и скорость читаются непосредственно из PORTSC.
Скорости xHCI выше 4 зависят от контроллера и выводятся как `unknown`.
Состояние `[HID active]` означает работающий драйвер клавиатуры/мыши;
`[no class driver]` — устройство определилось, но нужного драйвера нет.
Подробнее: [usb-hotplug.md](usb-hotplug.md).

`lsports` показывает все доступные корневые USB-порты и реализованные SATA-порты
обслуживаемого AHCI-контроллера, включая пустые. Для SATA выводятся состояние PHY,
скорость линии, сигнатура и, если диск был инициализирован, модель и размер.
В Live-сборке дисковый AHCI-драйвер остаётся выключенным: диагностика только
читает регистры уже включённого прошивкой контроллера. PCI decode, bus mastering,
команды диску и сбросы портов не включаются; внутренний диск не становится
блочным устройством и не подменяет RAM-корень. Если прошивка не включила MMIO
контроллера, данные портов недоступны. Для блочных устройств используется `lsblk`.
Сообщение `inventory unavailable` означает отсутствие источника данных, а не
отсутствие подключённого оборудования.

Ограничения: дополнительные xHCI-контроллеры, UHCI/OHCI/EHCI,
SuperSpeed-only хабы, HDMI/DP/audio jack detect и подписи физических разъёмов
пока не перечисляются/не обслуживаются. USB2-часть комбинированного USB3-хаба
поддерживается как USB2-хаб. Флешка видна в `lsusb`, но драйвера USB Mass Storage
для доступа к её данным ещё нет. PCI BDF и номера root-port/SATA — логические
адреса, не маркировка слотов и разъёмов на корпусе.

## Интерфейс программ

`hwinfo(kind, index, out, size)` из `myos.h`/`hwinfo.h` возвращает 1 при получении
записи, 0 в конце списка или отрицательный errno. Вид записи задают `HWINFO_PCI`,
`HWINFO_USB`, `HWINFO_SATA`, `HWINFO_USB_DEVICE`.
Последний возвращает текущие устройства, их route, parent_slot, hub_ports и generation. Для PCI index — начальный BDF, после записи нужно
продолжить с `((bus << 8) | (device << 3) | function) + 1`; 65536 — конец.
Для USB/SATA index — порядковый номер записи с нуля.

Новый системный вызов добавлен в конец таблицы; номера существующих сохранены.
Ядро проверяет размер и доступность буфера, копирует только готовую запись и
не меняет буфер при EOF. Доступ к PCI-конфигурации защищён общей блокировкой
CF8/CFC. Диагностика не сбрасывает порты и не записывает конфигурацию устройств.

Проверка: `make hardwaretest`. Тесты используют отдельные временные диски:
PCI-мост и multifunction-устройства, SATA с занятыми/пустыми портами на 1/4 CPU,
Live-загрузка с USB HID на 4 CPU, чтение дескрипторов, отключение мыши, ошибочные
указатели/размеры и буферы только для чтения. `disk.img` и готовый Live-образ
пользователя не изменяются.
