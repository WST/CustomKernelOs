# Запуск MyOS с USB на реальном ПК

Подготовлен отдельный **BIOS/CSM live-образ** `build/myos-usb.img`.
Обычные `make run` и `build/os.img` сохраняют прежний путь загрузки.

## Что работает в новом пути

* MBR с активным разделом MyFS; загрузчик читает ядро и файловую систему
  через BIOS INT 13h LBA. Копирование выше 1 MiB выполняется в protected mode.
* Проверка E820 и A20 до записи в высокую память. Ядро размещается с 1 MiB,
  RAM-диск с 16 MiB; оба диапазона зарезервированы в физическом аллокаторе.
* BIOS VBE: предпочтительное разрешение из EDID монитора или до 1920×1080
  при отсутствии EDID; 32-bit RGB, линейный framebuffer. Для NVIDIA и выбора
  режима см. [nvidia.md](nvidia.md).
  Драйвер использует фактический pitch, сохраняет BIOS-шрифт, рисует процессором.
  Режим можно менять из `mode` и Display через runtime VBE, если видеобиос
  успешно выполняется встроенным x86-интерпретатором. При несовместимости
  остаётся фиксированный framebuffer. Аппаратного ускорения NVIDIA нет.
  Ранний текст хранится в RAM, поскольку загрузчик уже включил графический
  режим и VGA-апертура 0xB8000 не является надёжным хранилищем текста.
  При поддержке PAT видеопамять отображается как write-combining (WC),
  иначе остаётся некэшируемой. Обычная RAM и MMIO-регистры устройств сохраняют
  прежние атрибуты. PAT настраивается до обращения к framebuffer на каждом CPU,
  включая AP; записи в видеопамять завершаются барьером памяти.
  Прокрутка консоли сравнивает текстовые ячейки в RAM и перерисовывает только
  изменившиеся символы и цвета. Она не читает физическую видеопамять для
  сдвига всего экрана; аппаратное копирование у SVGA/VirtIO сохраняется.
  Вывод блока текста обновляет курсор один раз в конце; одинаковые ячейки
  при печати и ANSI-очистке не рисуются повторно. Числовые параметры ANSI
  ограничены, чтобы переполнение не выводило курсор за границы консоли.
  Внутри блока VBE-консоль накапливает изменённые ячейки и рисует только
  итоговый экран. В тесте из восьми строк это 35 отрисовок символов вместо 188
  на сетке 10x4. Пользовательский `write()` обрабатывается порциями по 256 байт,
  между которыми планировщик может запустить USB-worker и другие задачи.
  Один большой вывод больше не удерживает ядро до обработки всего буфера.
* xHCI: BIOS ownership handoff, 32/64-байтные контексты, scratchpad buffers,
  command/event/transfer rings, polling без MSI. Поддерживаются непосредственно
  подключённые USB HID Boot Keyboard и Boot Mouse, включая составные устройства
  с соответствующими интерфейсами. Клавиши проходят через прежние раскладки
  и сочетания клавиш; есть программный автоповтор.
  Перед обнаружением устройств включается питание управляемых портов и
  выдерживается пауза 100 мс. В лог выводятся PCI-адрес контроллера,
  подключённые порты, PORTSC и ошибки сброса/настройки.
  Пока используется только первый найденный xHCI-контроллер; USB-хабы
  и подключение устройств после начального обнаружения не поддерживаются.
* Файловая система с программами загружается в RAM. Драйвер накопителей в
  live-режиме скрывает внутренние ATA-диски. Изменения **теряются при выключении**.
* Сеть: добавлен начальный backend Intel I219-V для 100/200-series PCH,
  включая контроллер платы MSI B250M GAMING PRO. Адрес запрашивается у роутера
  по DHCP после появления линка. Проверены модель регистров и сетевые модели
  QEMU; работа физического I219-V пока требует проверки на плате.
  Поддерживаемые PCI ID, диагностика и тесты описаны в [ethernet.md](ethernet.md).

## Сборка

В Linux/WSL с обычными зависимостями проекта:

```sh
make -j4 usb-image
make usbtest
```

`make consoletest` проверяет реальный код консоли с RAM-framebuffer под
ASan/UBSan: цвета и пиксели после прокрутки, пакетное обновление курсора,
повторную очистку, ограниченный вывод с NUL, длинные ANSI-параметры и
приостановку/восстановление консоли.

`make consoleloadtest` запускает один `write()` на 512 KiB и проверяет, что
PIT продолжает тикать и USB-мышь обрабатывается до окончания записи. Программа
устанавливается только в временную копию USB-образа; исходные образы остаются
неизменными. В QEMU/TCG проверенный вызов занял 1610 мс гостевого времени;
это проверка отзывчивости, а не измерение скорости видеопамяти реального ПК.
`usbtest` также проверяет PAT/WC с двумя CPU и fallback при отсутствии PAT.

`usb-image` копирует `disk.img` в `build/hardware/live-root.img` и обновляет
программы только в копии. Удаляет `/etc/accounts` только в live-копии, поэтому
при каждой загрузке USB требуется первоначальное создание пароля root.
Автозапуск `desktop.service` отключается только в live-копии: рабочий стол
запускается командой `desktop` после входа.
Существующий `disk.img` не перезаписывается. Размер live-корня ограничен 64 MiB.
SHA-256 и раскладка образа находятся в `build/hardware/manifest.json`.

## Логи запуска

Перед инициализацией подсистем ядро выводит `[BOOT]`: память, paging, куча,
framebuffer, планировщик, ввод, USB, сеть, накопители, MyFS, SMP и службы.
Если запуск останавливается, последняя такая строка указывает этап, в который
ядро вошло. Сообщения `[OK]` и `[FAIL]` уточняют результат; отсутствие
необязательного сетевого адаптера не останавливает загрузку.

Дополнительно выводятся адрес и размер RAM-корня, параметры VBE от BIOS,
граница управляемой RAM, адрес/pitch framebuffer и число запущенных CPU.
USB-лог содержит PCI-адрес, MMIO, версию xHCI, число слотов и scratchpad-буферов,
управление питанием и состояния подключённых портов. Сообщения идут в консоль
и существующий последовательный вывод (в QEMU — serial log); отдельный файл
лога на флешку не записывается.

## Запись и запуск

1. Используйте отдельную флешку. Запишите `build/myos-usb.img` как **сырой образ
   всего устройства**, а не как файл на разделе. Запись уничтожает прежнее
   содержимое выбранной флешки. Сам процесс сборки ничего на флешку не записывает.
2. Для первого теста отключите внутренние накопители.
3. В BIOS включите CSM/Legacy Boot, отключите Secure Boot, оставьте Legacy USB
   Support включённым для загрузчика. Названия и наличие опций зависят от платы.
4. Подключите клавиатуру и мышь непосредственно к материнской плате, без хаба,
   док-станции или монитора с USB-хабом. Подключайте до включения ПК.
5. В Boot Menu выберите Legacy-вариант флешки (без префикса `UEFI:`).
6. Создайте пароль root, войдите и выполните `desktop` для рабочего стола.

## USB-мышь: границы экрана и колесо

Границы указателя задаются по framebuffer и при USB-only загрузке, даже если
PS/2-контроллер отсутствует. Драйвер xHCI читает HID report descriptor мыши и
включает report protocol: поддержаны Report ID, относительные X/Y по 8/12/16
бит и Wheel. При неподдерживаемом дескрипторе сохраняется boot-режим без колеса.
Колесо поступает рабочему столу и приложениям, поддерживающим прокрутку.
Проверки: `make usbmousetest`, `make usbmouse-smoke`.

Если доступен только загрузочный видеорежим, команда `mode` сообщает об отказе
runtime VBE. Для вывода только диагностики без прокрутки: `dmesg | grep VBE`.
Строки содержат вызов BIOS, AX, адрес остановки, исключение или запрещённый
I/O/MMIO. По ним можно проверить совместимость физического видеобиоса;
один доступный режим сам по себе не доказывает ограничение монитора или карты.
