# Устройства, разделы и единое дерево каталогов

MyOS использует VFS: пути проходят через единое дерево, а MyFS хранит данные
каждого тома независимо. Формат существующего `disk.img` не изменён.

## Команды

```
lsblk
ls /dev
mount
mkdir /mnt/data
mount /dev/sdb2 /mnt/data
echo hello > /mnt/data/test.txt
cat /mnt/data/test.txt
cd /mnt/data
pwd
cd ..
```

`mount` без аргументов показывает подключённые MyFS и devfs. До четырёх MyFS
могут быть подключены одновременно, включая корневой том. Повторное подключение
одного устройства и пересекающихся диапазонов диска запрещено. Переименование
между томами возвращает EXDEV. Точки монтирования и их предки защищены от
переименования и удаления. Форматирование корня при других активных томах запрещено.

`/dev` существует виртуально, не занимает inode на диске и содержит:

* `/dev/sdb` — весь диск, подключённый к существующему primary-slave ATA-драйверу;
* `/dev/sdb1` … `/dev/sdb4` — допустимые первичные разделы MBR;
* `/dev/sdc` — второй ATA-диск, secondary master (QEMU `index=2`);
* `/dev/sdc1` … `/dev/sdc4` — его первичные разделы;
* `/dev/null` — чтение возвращает EOF, запись поглощается;
* `/dev/zero` — чтение возвращает нулевые байты, запись поглощается.

Блочные устройства доступны программам только для чтения. Запись MyFS идёт
через внутренний блочный API с проверкой границ раздела. У файловых смещений
пока 32 бита: чтение сырого устройства ограничено первыми 4 GiB минус один байт.

На диске без MBR корнем остаётся прежняя MyFS. При наличии MBR корнем становится
первый допустимый раздел с корректной MyFS. Неизвестные и повреждённые ФС
не форматируются автоматически. Совместимость создания старых пустых образов
сохранена: автоматическое создание MyFS разрешено только на диске без MBR,
если весь первый сектор нулевой. Это не проверка пустоты остальных секторов.

## Новый образ с разделами без изменения исходного

Сначала соберите проект (`make`). Создайте второй небольшой том:

```sh
truncate -s 2M build/data-myfs.img
build/myfs build/data-myfs.img mkdir /data
python3 tools/partition_image.py build/partitioned.img disk.img build/data-myfs.img
make run DISK=build/partitioned.img
```

Утилита копирует исходные тома в новый MBR-образ, не изменяя их. Выходной файл
должен отсутствовать. Таблица использует тип 0x83; содержимое разделов — MyFS,
а не ext2/ext4. Разделы не создаются на реальном оборудовании.

При запуске нового образа `/dev/sdb1` содержит корень, а `/dev/sdb2` можно
подключить командой `mount /dev/sdb2 /mnt`. После перезагрузки дополнительный
том нужно подключить снова; записанные файлы сохраняются.

## Каталоги

`make install` создаёт `/home`, `/root`, `/tmp`, `/var/lib`, `/var/log`, `/usr/bin`,
`/usr/lib`, `/usr/share`, `/mnt`, `/media`, `/run`, `/proc` и `/sys`, дополнительно
к существующим `/bin`, `/etc`, `/lib`, `/include` и `/src`. `/tmp` и `/run`
пока обычные постоянные каталоги MyFS, `/proc` и `/sys` — пустые каталоги,
зарезервированные для будущих виртуальных ФС.

## Диск на 1 GiB и разметка внутри MyOS

Закройте прежний QEMU перед повторным запуском. На компьютере в WSL создайте
**новый** файл диска. Эксклюзивный режим `xb` откажется перезаписывать существующий:

```sh
python3 -c "with open('data-1g.img', 'xb') as f: f.truncate(1073741824)"
make run DATA_DISK=data-1g.img
```

`disk.img` останется системным диском `/dev/sdb`, а `data-1g.img` появится как
`/dev/sdc`. В MyOS выполните:

```sh
lsblk
fdisk init /dev/sdc --yes
fdisk add /dev/sdc 1 1 512
fdisk add /dev/sdc 2 513 511
fdisk /dev/sdc
mkfs /dev/sdc1 --yes
mkfs /dev/sdc2 --yes
mkdir /mnt/data
mount /dev/sdc1 /mnt/data
echo hello > /mnt/data/test.txt
cat /mnt/data/test.txt
```

Аргументы `fdisk add`: устройство, номер первичного раздела (1–4), начало в MiB,
размер в MiB. Здесь первый раздел — 512 MiB, второй — 511 MiB; первый MiB занят
выравниванием и MBR. Для одного раздела почти на весь диск: после `init` используйте
`fdisk add /dev/sdc 1 1 1023`. Для полного тома ровно 1 GiB можно создать новый
сырой MyFS-образ без разделов через `make DISK=new-root.img DISK_MB=1024`.

`fdisk del /dev/sdc 2 --yes` удаляет запись раздела. `init` очищает все записи
разделов, `mkfs` создаёт новую ФС: прежние данные выбранного тома станут недоступны.
Эти операции требуют явного `--yes`. Изменить существующий раздел командой `add`
нельзя: она принимает только свободный слот. Размер раздела ограничен 1 GiB.
Некорректные диапазоны, пересечения и выход за диск отклоняются до записи.

Разметка запрещена, если на диске есть хотя бы один подключённый том. Форматирование
запрещено для подключённого тома и диапазонов, пересекающих его; открытые сырые
дескрипторы диска также блокируют административные записи. GPT и редактирование
таблиц с неизвестными типами разделов не поддерживаются. Загрузочный диск QEMU
(`index=0`) не публикуется в `/dev` и недоступен этим командам.

После перезагрузки повторите `mount`; форматировать повторно не нужно.

### Совместимость и размеры

MyFS поддерживает до **1 GiB на том** и до **16 384 inode** (один зарезервирован).
Число inode выбирается при форматировании пропорционально размеру тома, минимум 256.
Каждый файл по-прежнему ограничен примерно 8 MiB; имя — 27 байт. Карта свободных
блоков выделяется из кучи по размеру тома, а поиск свободных блоков использует
сохранённую позицию, чтобы запись больших объёмов не начинала поиск каждый раз с нуля.

Старые образы читаются без преобразования и сохраняют прежний размер ФС и число inode.
Увеличение файла-образа само по себе ФС не расширяет, и расти на месте она пока не умеет.
`build/myfs disk.img grow 64` копирует файлы в новый образ указанного размера
(в мегабайтах, от 1 до 1024) и оставляет прежний файл как `disk.img.bak`.
Число inode по-прежнему выбирается при создании тома: 64 МБ — 1024 inode, 1 ГиБ — 16384.

## Границы реализации

* Два ATA PIO-диска: primary slave и secondary master. NVMe, AHCI и USB
  не реализованы; названия `/dev/nvme0n1` появятся вместе с NVMe-драйвером.
* Только четыре первичных раздела MBR. GPT и расширенные разделы не монтируются
  и не форматируются автоматически. Пересекающиеся/выходящие за диск записи пропускаются.
* Файловый драйвер пока только MyFS: 1 GiB и до 16 384 inode на том, имя до 27 байт.
  Нет совместимости ext4, символьных ссылок, владельцев и Unix-прав доступа.
* Пока нет `umount`, `/etc/fstab` и загрузки boot-образа из раздела. Загрузочный
  `build/os.img` остаётся отдельным диском QEMU. Для отключения томов — перезагрузка.
* Установка `.deb` и Linux ABI не входят в эту реализацию.

## Проверка

`make test` проверяет прежние операции MyFS и кучу, devfs, границы разделов,
два тома, переходы через точки монтирования, защиту занятого диска и отказ от
форматирования повреждённых метаданных. `make vfstest` собирает систему и запускает
QEMU без окна на отдельных тестовых образах: сырой диск, MBR, монтирование,
чтение/запись и повторная загрузка. Логи находятся в `build/vfs-*.serial.log`.
Также проверяются `fdisk` и `mkfs` на отдельном диске 1 GiB с разделами 512/511 MiB,
защита корневого диска и чтение файла после повторного запуска QEMU.
`make largetest` использует отдельный разреженный образ 1 GiB: создаёт 40 MiB данных
и более 256 файлов, проверяет выделение за границей 32 MiB, последний сектор и remount.
