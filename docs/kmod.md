# Загружаемые модули ядра

Ядро остаётся одним плоским бинарником. Драйвер, который нужен не на каждой
машине, лежит отдельно: ELF32 `ET_REL`, машина `EM_386`, файл `/boot/modules/*.ko`.
Релокации только `R_386_32` и `R_386_PC32`. Чужой тип загрузчик отвергает.

Модуль собирается тем же freestanding `-m32`, без PIC, и связывается
`ld -r -m elf_i386`. Загрузчик копирует секции с `SHF_ALLOC` в кучу ядра,
применяет релокации и вызывает `init` из символа `myos_module`. На этом i386
без PAE у страниц кучи нет бита NX, поэтому код модуля исполняется оттуда.
Секции без `SHF_ALLOC` (например `.eh_frame`) пропускаются. Выравнивание
секции — степень двойки до 4096 байт: GCC ставит `.bss` на 32, если в ней
есть массив такого размера, а куча сама даёт только 16.

Неразрешённый символ ищется в таблице `kexports`. Таблица держит адреса
функций ядра, поэтому `--gc-sections` их не выбрасывает. Снаружи модуля
доступны PCI, страницы, куча, `kprintf`, сон, `firmware_read`, регистрация
`netif` и `wlan`.

Идентификаторы устройства живут в исходнике модуля, не в `kmain`:

```c
MYOS_MODULE(iwl1000);
MYOS_PCI_ID(0x8086, 0x0083);
MYOS_PCI_ID(0x8086, 0x0084);
```

`tools/gen_modalias.py` пишет `/boot/modules/aliases` строками
`8086 0084 iwl1000.ko`. После монтирования MyFS ядро обходит PCI и загружает
совпавший файл. Класс устройства сам по себе модуль не выбирает. Повторный
обход — `kldload` через `SYS_MODCTL`: загрузка, выгрузка, список, повторный
обход. Выгрузка занятого модуля возвращает `EBUSY`.

Прошивка читается уже смонтированным томом, тем же путём, что `/etc/display`.
`firmware_read` копирует файл в память ядра и не принимает пустой файл.

Проверка: `make kmodtest` — релокации учебного `.ko`, отказ типа 99,
выгрузка и обе строки aliases для Centrino N 1000.
