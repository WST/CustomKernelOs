# Правила работы с кодом MyOS

Эти правила действуют на весь репозиторий. Личные пожелания разработчика
подключаются из `AGENTS.local.md` в корне. Если файл есть, читай его вместе
с этим документом; при расхождении следуй локальному. В репозитории его нет
намеренно: каждый заводит копию у себя. Не создавай `AGENTS.local.md` и не
добавляй его в коммит.

@AGENTS.local.md

## Порт, а не пакет

Программа, которую ставят через `ext` (`ext/instructions/<имя>`, каталог
`/ext`), называется **портом**. В документации, комментариях и сообщениях
пользователю пиши «порт».

Слово «пакет» для этого не используй. Оно зарезервировано под будущий
пакетный менеджер, и раньше времени смешает две разные вещи.

```
плохо:  ext install ставит пакет lua
хорошо: ext install ставит порт lua
```

Так же по-английски: port, не package. Имена, которые уже входят в интерфейс,
не переименовывай заодно с формулировкой: `EXT_AUTOINSTALL_PACKAGES`, поля
структур и ключи конфигурации остаются, пока нет отдельной задачи на смену ABI.

«Пакет» в других значениях остаётся на своём месте: сетевой или USB-кадр,
пакет мыши, пакет процессора, пакеты дистрибутива на компьютере сборки.

## Как устроен код

Ядро, libc, оболочка, рабочий стол, сеть, браузер и `cc` написаны для MyOS.
Ядро — свободностоящий C для i386, без заголовков хоста. Программы
пользователя собираются против `user/lib` и стартуют в кольце 3.

`user/lib/openssl` и `user/lib/curl` — чужие деревья. Их не переписывают под
стиль MyOS. Правка там только та, без которой порт или связка `wget` /
`download` не собирается.

Новый чужой исходник приходит рецептом в `ext/instructions`, ставится в `/ext`
и не подменяет одноимённый файл из `/bin`.

Номера системных вызовов и формат MyFS на диске — совместимость. Новый вызов
добавляется в конец, смена раскладки тома получает следующую версию и строку
в `docs/`, а не тихую перезапись старого суперблока.

Комментарии в своём коде — по-русски и про ограничение, которое иначе не видно
из следующей строки. Имена в коде — по-английски. Документы в `docs/` и
`README.md` — по-русски. Описание системы живёт в `README.md`, устройство
подсистем — в `docs/`, порты — отдельно и по имени «порт».

Секреты, `.env`, образы дисков и `AGENTS.local.md` в коммит не входят.

## Коммит

Перед коммитом просмотри каждый файл в индексе. В коммит входит только то,
что относится к сделанной работе. Настройки редактора, каталоги `.vscode` и
`.idea`, сгенерированные отчёты, кэши и прочий вывод инструментов туда не
попадают, даже если они уже лежат в рабочем дереве.

## Проверка

Поведение, которое меняешь, прогоняй уже существующей целью `make` для этой
подсистемы (`make test`, `make exttest`, `make cctest` и соседние). Новую
проверку клади рядом с прежними тестами того же слоя, а не отдельным
сценарием без входа в `Makefile`.
